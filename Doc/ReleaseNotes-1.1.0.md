# ADOFAI Editor Tweaks - Chart Rendering 1.1.0

这是我接手维护 ADOFAI Editor Tweaks - Chart Rendering 后发布的第一个版本。本次更新覆盖 1.0.3 到 1.1.0，带来了多项编码能力、渲染流程和稳定性方面的改进。

部分渲染改进移植自 sui 的 CheryTools AET Recorder，已获作者同意。感谢 lizi 审核代码，也感谢参加内测的朋友们。

## 下载与安装

1. 下载下方附件 `ADOFAI.EditorTweaks.ChartRendering-1.1.0.zip`（约 86 MB，已自带 FFmpeg）。
2. 将压缩包解压到游戏目录的 `Mods\` 文件夹中；已安装旧版的用户可以直接覆盖。建议提前备份原来的 `Mods\ADOFAI.EditorTweaks.ChartRendering\` 文件夹。
3. 启动游戏，在编辑器中按 **F8** 打开设置页。旧版升级的用户如果之前保存过 `Ctrl+Shift+E`，可以在 UMM 面板里改成 F8（新默认值只影响新安装）。

需要 Unity Mod Manager 0.27.0 或更新版本。

Creplay 等调用本 Mod API 的 Mod 无需更新即可继续使用当前版本。注意：当音频缓冲区设置超过 256 时，渲染后可能出现 Creplay 按键音丢失的问题，详见「已知问题」。

## 升级前请注意

- **码率为 0（默认）时，改为按画质（CRF）编码。** 1.0.3 使用的是带上限的可变码率，因此同一张谱面的导出文件体积可能与旧版不同。需要固定码率时，请填写视频码率，或启用新增的「恒定比特率」。
- 安装包增大到约 86 MB，这是因为内置 FFmpeg 更换为完整版，以支持更快的 AV1 编码和 H.266。

## 新增

### 编码格式

- 除 H.264 外，新增 **HEVC/H.265**、**AV1**、**ProRes 422 HQ** 三种编码格式。
- 新增 **H.266/VVC**（实验性，不推荐）：目前只能使用 CPU 编码，速度非常慢，且大多数播放器和网站尚不支持，仅供尝鲜。

### 硬件编码

- 除 NVIDIA 外，新增 **AMD** 和 **Intel** 独立显卡、集成显卡的硬件编码支持。
- 默认按照 NVIDIA → AMD → Intel 的顺序自动选择，也可以在「详细编码设置」中手动指定。指定的显卡不可用时，会自动回退到 CPU 编码。
- AV1 硬件编码需要 NVIDIA RTX 40 系、AMD RDNA 3、Intel Arc 或更新的显卡。较旧的显卡会使用 CPU 的 SVT-AV1 编码器，速度相比此前也有明显提升。

### 编码器检测

- 总览页显示当前电脑可用的编码器。
- 渲染设置中会显示本次渲染实际使用的编码器，不可用的选项会置灰。
- 切换 GPU 或 FFmpeg 会触发重新检测。更新显卡驱动后，请手动点击「重新检测」以刷新编码器列表。

### 画质与速度

- **恒定比特率（CBR）**：可在高级设置中启用，按照填写的码率输出。码率填写为 0 时使用推荐码率。
- **编码预设**：在「详细编码设置」中可以选择编码器（显卡 / CPU / 自定义），并选择对应的速度预设。显卡编码提供 p1–p7，CPU 编码提供 ultrafast–veryslow。

### 画面

- **游戏画面模式支持高分辨率**：现在可以输出高于显示器实际分辨率的画面，例如在 1080p 屏幕上输出 4K 视频，屏幕上仍只显示预览画面。

### Web 设置页

- **默认快捷键改为 F8**：旧版的 `Ctrl+Shift+E` 会和编辑器快捷键冲突；新安装默认使用 F8，已有设置不会被自动覆盖，可以在 UMM 面板修改。
- **打开方式**：可以选择「自动 / Steam 覆盖层 / 系统浏览器」。自动模式优先尝试 Steam 覆盖层，不可用时回退系统浏览器；想固定行为可以直接选择「系统浏览器」或「Steam 覆盖层」。
- **局域网访问（实验性，默认关闭）**：开启后同一局域网的手机/平板可以打开设置页查看渲染进度。页面会显示带控制令牌的局域网地址，请勿公开；需要外网访问时建议使用 Tailscale / ZeroTier 等组网工具，不要把端口直接暴露到公网。

### 稳定性与诊断

- **关闭保护**：渲染过程中第一次尝试关闭游戏时会被拦截并提示，10 秒内再次尝试关闭才会真正退出。
- **断线提示**：游戏关闭或崩溃时，设置页会显示提示，说明渲染可能已经中断。
- **渲染日志**：每次渲染都会单独保存日志，路径为 `Workspace\Logs\render_*.log`，最多保留最近 10 份。反馈问题时可以一并提供。
- **自定义 FFmpeg 路径**：支持使用自己的 `ffmpeg.exe`；如果指定路径无效，则自动回退到内置 FFmpeg。

## 改进

- **进度显示更清晰**：进度条分为三个阶段：画面捕获 0–90%、视频编码 90–92%、音频合成 92–100%。进入音频合成阶段后会提示「请勿关闭游戏」。
- **避免导出不完整的视频**：视频会先写入 `.part` 临时文件，全部处理完成后再重命名。导出目录中使用正式文件名的视频因此不会是尚未完成的文件。
- **自动处理不兼容的格式组合**：选择 ProRes 时自动切换为 MOV 容器；MOV 容器下选择 FLAC 音频时会自动改为 ALAC（同为无损格式）。不兼容的选项会置灰，鼠标悬停可以查看原因。
- **ProRes 编码优化**：编码速度提升约 3 倍，输出文件体积也更加合理。
- **渲染结束后自动返回编辑器**：不再需要手动按 Esc 返回。
- **写入视频阶段保持播放状态**：画面捕获完成、正在编码或合成音频时，编辑器会保持播放状态，不会提前回到编辑器让人误以为已经结束；这个阶段按 Esc 不会取消渲染，需要取消请用设置页的「取消渲染」按钮。
- **取消渲染更可靠**：取消操作得到改进，取消后会清理尚未完成的视频文件。
- **减少不必要的帧复制**：重复帧处理不再额外复制整帧画面，因此高分辨率渲染速度更快。
- **临时文件管理改进**：每次渲染都会使用独立的临时文件夹，取消后可以立即开始下一次渲染。当新的渲染开始时，会自动清理遗留超过 1 小时的临时文件夹。
- **改善苹果设备兼容性**：HEVC 视频使用 `hvc1` 标签，提升在苹果设备上的直接播放兼容性。

## 修复

- 修复同一张谱面第二次开始渲染时，导出视频没有音乐的问题。
- 修复视频中的星球自转、彩虹星球、Miss 闪光、打击停顿、镜头后坐、文字装饰抖动等效果播放速度比游戏内更快的问题。
- 修复渲染过程中点击「取消」没有反应的问题，尤其改善了 CPU 慢速预设下的取消体验。
- 修复音频合成阶段进度显示停留在 100% 不动的问题；此前此时关闭游戏还可能留下损坏的视频。
- 修复选择 HEVC、AV1、ProRes 后，实际输出仍然是 H.264 的问题。
- 修复 ProRes 渲染失败的问题。
- 修复 MOV 格式搭配 FLAC 音频时合成失败的问题。
- 修复音频缓冲区大于 256 时，官方谱面或 Bundle 谱面渲染失败的问题。
- 修复音频缓冲区切换失败后，原有音频设置没有恢复的问题。
- 修复自定义 FFmpeg 路径包含非法字符时，渲染直接报错的问题。
- 修复「Finalizing video」阶段的文字没有翻译的问题。
- 修复 4K/2K 渲染收尾等待 GPU 回读时可能卡住或超时的问题，避免在回读未完成时释放捕获纹理；连续 4K 渲染更稳定。
- 修复 Steam 覆盖层中设置页下拉菜单位置错位、遮挡状态栏的问题。
- 修复 AMD 核显 + 独显机器上 HEVC/AV1 AMF 被误判为不可用的问题。编码器探测分辨率从 256×256 改为 640×360：AMF 的 HEVC 要求宽度至少 384、AV1 至少 320，原来的窄画面会在初始化阶段失败。

## 已知问题

- **AMD / Intel 硬件编码**尚未在所有显卡上完成验证。遇到问题时，可以在「详细编码设置」中改用 CPU 编码，并反馈显卡型号和驱动版本。
- **CBR 支持范围有限**：NVIDIA 和 AMD 显卡编码支持真正的恒定比特率；CPU 编码只能做到近似恒定；H.266 不支持 CBR，会改用可变码率；ProRes 的码率由格式本身决定，CBR 对其无效。
- **H.266 编码速度很慢**：1080p60 大约每秒只能编码几帧，仅建议对短片段进行尝试。
- **音频缓冲区大于 256 时的兼容性问题**：渲染过程中会临时切换音频设置。渲染结束后，其他 Mod 自行加载的音效可能受到影响，例如 Creplay 的按键音可能丢失。通常需要重新进入谱面才能恢复。
- **多显卡自动选择**：当电脑同时存在多块显卡时，自动选择按照 NVIDIA → AMD → Intel 的顺序进行，不会根据游戏实际使用的显卡进行判断。必要时请手动指定编码显卡。
- **AMD 核显 + 独显**：如果 AMF 仍然默认使用核显，可以在 Windows 图形设置中给 `Mods\ADOFAI.EditorTweaks.ChartRendering\ThirdParty\FFmpeg\ffmpeg.exe` 指定「高性能」GPU。640×360 的检测修复解决的是误判，不改变 Windows 的默认适配器选择。
- **局域网访问**：目前使用 HTTP 加一次性控制令牌，建议只在可信局域网内使用；需要外网访问时请用 Tailscale / ZeroTier 等组网工具，不要把端口直接暴露到公网。

## 给 Mod 作者

公共 API（`ADOFAI.EditorTweaks.Api.Rendering`）本次只进行了向后兼容的扩展，原有调用方无需修改代码。

新增或扩展的内容包括：

- `ChartRenderRequest.VideoCodec` 和 `ChartRenderVideoCodec`（`H264`、`Hevc`、`Av1`、`ProRes`、`Vvc`）
- `ChartRenderRequest.HardwareEncoder` 和 `ChartRenderHardwareEncoder`（`Auto`、`Nvidia`、`Intel`、`Amd`）
- `ChartRenderRequest.HardwarePreset` / `CpuPreset` 及对应枚举
- `ChartRenderRequest.ConstantBitrate`
- 游戏画面模式现在会使用请求中的 `Width` / `Height`；宽高为 0 时仍按窗口尺寸截屏。

请注意，码率为 0 时的默认编码行为已从带上限的可变码率改为 CRF，可能影响最终成片的文件体积。

API 文档位于仓库中的 `Doc/Api/ChartRendering.md`。

## 反馈问题

如果遇到问题，请在 Issues 中尽可能提供以下信息：

- 显卡型号和驱动版本；
- 游戏版本；
- 选择的编码格式和容器；
- 对应的 `render_*.log`；
- `Player.log`，路径为 `%USERPROFILE%\AppData\LocalLow\7th Beat Games\A Dance of Fire and Ice\Player.log`；
- 问题的具体复现步骤。

提供这些信息有助于定位编码器、渲染流程或游戏环境相关的问题。
