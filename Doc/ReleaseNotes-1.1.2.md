# ADOFAI Editor Tweaks - Chart Rendering 1.1.2

这一版解决两个最常被提到的问题：**视频太大**和**设置页太乱**。新增画质档位，默认给码率设上限；设置页重新分类；平板看进度不用再复制链接；出问题时可以一键导出诊断包。另外修复了两个 JRP 雨条不显示的问题。

感谢 lizi 审核代码并修复了审核中发现的问题，也感谢参加内测的朋友们。

## 下载与安装

| 安装包 | 大小 | 说明 |
|---|---:|---|
| `ADOFAI.EditorTweaks.ChartRendering-1.1.2.zip` | 约 0.35 MB | 首次使用时自动下载 FFmpeg（推荐） |
| `ADOFAI.EditorTweaks.ChartRendering-1.1.2-Full.zip` | 约 88 MB | 已自带完整版 FFmpeg，适合离线安装 |

用 UMM 或 Aurora 安装，或者解压到游戏目录的 `Mods\` 文件夹覆盖旧版。建议先备份 `Mods\ADOFAI.EditorTweaks.ChartRendering\`。

需要 Unity Mod Manager 0.27.0 或更新版本。Creplay 等调用本 Mod 的 Mod 不需要更新。

## 升级前请注意

- **默认画质改为“标准”档，视频会比以前小。** 1.1.0 / 1.1.1 在码率为 0 时不限码率：粒子多的谱面，1080p60 实测平均约 71 Mbps（3 分钟约 1.6 GB），默认画质下还会更大。现在默认按 YouTube 推荐上传码率的 2 倍设上限，1080p60（H.264）最多 24 Mbps，3 分钟最多约 540 MB。
- **想完全恢复 1.1.1 的行为**：在「画质与编码」页打开「详细编码设置」，档位会变成「自定义」，把画质参数填回原来的值、码率填 0 即可。不要把「近似无损」当成旧版——它是固定的高画质档，比旧版默认更清晰，也更大。
- 覆盖安装后会自动使用「标准」档，其他设置不变。
- **1.1.1 留下的临时文件需要手动删除。** 1.1.1 每次渲染都在工作区留下一个 `CurrentRender_…` 文件夹（可能有好几 GB）。新版只自动清理自己创建、带标记的文件夹，旧版留下的不会动。确认游戏没有在渲染后，打开 `Mods\ADOFAI.EditorTweaks.ChartRendering\Workspace\`，删掉里面的 `CurrentRender_…` 文件夹即可。

## 新增

### 画质档位

在「画质与编码」页按用途选一个档位就够了：

| 档位 | 适合 | 码率上限（1080p60 / 4K60，H.264） | 编码速度 |
|---|---|---|---|
| 小文件 | 发给朋友、手机看 | 12 / 60 Mbps | 偏快 |
| **标准（默认）** | 上传 B 站 / YouTube | 24 / 120 Mbps | 均衡 |
| 高质量 | 自己存档 | 48 / 240 Mbps | 偏慢、压缩更好 |
| 近似无损 | 导入剪辑软件 | 不限 | 偏慢、压缩更好 |

- 前三档按画质编码、码率有上限：画面简单时文件更小，粒子再多也不会超过上限（超出时画质会稍微下降）。上限会预留编码器超调的余量。
- HEVC、AV1、VVC 同画质需要的码率更低，上限分别按 ×0.7 / ×0.6 / ×0.5 折算；4K60 的 HEVC 标准档约为 84 Mbps。
- 上限以 YouTube 推荐上传码率为基准，都高于 B 站的最低要求。
- 档位同时决定编码速度（「编码速度」保持「跟随档位」时）。需要时可以在「详细编码设置」里手动调整。
- 手动修改画质参数或码率后，档位变为“自定义”，行为和 1.1.1 一样；可以一键恢复「标准」档。
- 恒定码率优先于档位；ProRes 忽略档位。
- **AV1 要注意兼容性**：同画质下 AV1 文件最小，但部分剪辑软件（例如 Premiere Pro）不能导入 AV1 视频。之后要剪辑的话，请用 H.264 或 HEVC（HEVC 的兼容性比 AV1 好），或者直接选“剪辑用”预设（ProRes）。

### 文件大小预估

- 每个档位显示当前谱面“**通常约**多少、**最多约**多少”。“最多约”是保证值；“通常约”是估算，渲染过一次后会按你的实际结果估算，越用越准。
- 渲染中按已经写出的数据推算最终大小；渲染完显示实际大小、平均码率和“达到上限的百分比”。
- 开始渲染前会检查：硬盘空间是否够（成片加同样大的临时文件）、是否可能超过 B 站 16 GB 上限、帧率是否超过平台支持。

### 预设和分享码

- 一键预设：B 站 1080p60、B 站 4K60（HEVC）、YouTube 4K60、4K 存档、剪辑用（ProRes）、快速预览（720p30）。
- 可以把渲染设置复制成分享码发给别人，对方粘贴即可导入。分享码只包含渲染设置，不含文件夹路径、快捷键或设备信息。

### 设置页重新分类

- 分为：总览 / 渲染 / 输出 / 画质与编码 / 画面与音频 / 网页与连接 / 工具与诊断。
- 每一页顶部都能看到渲染进度和开始/取消按钮。
- 总览页用普通的话说明这台电脑能用哪些视频格式，并显示游戏版本和构建号（例如 3.4.0（r150））。
- 手机上导航改为横向滚动。

### 用手机 / 平板看进度

- 「网页与连接」页显示二维码，扫码打开一次后这台设备会被记住，**存成书签**以后就能直接打开，不用每次复制链接。
- 局域网端口默认 18200（可修改），被占用时会自动往后找一个可用端口，建议在路由器里给电脑固定 IP。
- **只读链接**：只能看进度，不能开始、取消或改设置，适合发给别人看。
- **忘记所有设备**：让所有已记住的设备和只读链接失效，本次的访问链接也会换新，需要从游戏里重新打开设置页。

### 选择文件夹

- 导出目录和工作区目录旁边有“浏览…”，在网页里逐级点选文件夹，在 Steam 覆盖层和平板上也能用。
- “打开”按钮直接在资源管理器里打开对应文件夹。

### 诊断包

- 「工具与诊断」页点“导出诊断包”，会把最近的渲染日志、游戏日志（必要时包含上一次）、电脑和编码器信息打包成一个 zip。
- 包里附带一份《日志分析指南》。把 zip 发给 AI 并说一句“请按诊断包里的《日志分析指南》分析问题”，就能得到初步的分析；也可以直接发给开发者。
- 诊断包会去掉访问令牌、只读链接和 Windows 用户名。
- **诊断模式**：记录更详细的日志，并保留渲染的临时文件，排查问题时再打开。

## 改进

- **临时文件自动删除**：渲染完成、取消或合成失败后，立即删除这次的原始视频和音频（它们和成片差不多大）。以前成功渲染后不删，只在下一次渲染时删除一小时以前的，工作区会越积越大。游戏崩溃或强关留下的，会在下次渲染或启动游戏时清理；「工具与诊断」页可以看到占用并手动清理（会先确认，也会清掉诊断模式保留的文件）。自动清理只删本 Mod 创建并做了标记的文件夹，不会误删工作区里的其他东西。
- **游戏日志里不再写访问令牌**，发日志给别人更安全。
- “回读格式”从音频设置移到了画面捕获里。
- 工作区目录的说明改为：建议放在固态硬盘上；有两块硬盘时和导出目录分开放，合成更快。

## 修复

- 修复经 JALib 安装的 JRP（程序集名为 `JipperResourcePack-JAMod…`）在离屏渲染时雨条完全不显示的问题。
- 修复 JRP 在密集段或较慢的雨速设置下，雨条池用完后新的雨条一直不可见的问题。现在会按雨条存活时间准备足够的数量，渲染中不够时自动补充，并保证不会在离屏画布下新建雨条。
- 修复 JALib 在渲染开始后才加载出正在运行的 JRP 按键显示时，兼容适配仍然挂在旧程序集上、雨条不跟随视频时间的问题。（lizi）
- 只读链接收到的进度信息里不再带渲染器和 FFmpeg 消息，避免露出本地路径。（lizi）
- 浏览器不允许写剪贴板时，“复制分享码”“复制只读链接”会弹出手动复制框，而不是没有反应。（lizi）
- 使用自定义编码参数时，设置页不再按画质档位估算文件大小。（lizi）

## 已知问题

- **画质参数还在校准中**：各档位的画质值是初稿。如果觉得某个档位偏糊或偏大，欢迎附上档位、编码格式、显卡型号、成片大小和截图反馈。
- **“通常约”是估算**：粒子多的谱面会比“通常约”大，但不会超过“最多约”。
- **AMD / Intel 显卡**的档位参数还没在所有显卡上验证。遇到报错可以在「详细编码设置」里改用 CPU 编码，并反馈显卡型号和驱动版本。
- **libaom-av1**（只在没有 SVT-AV1 时使用）只能控制平均码率，局部可能高于上限。
- **局域网访问使用 HTTP**，建议只在可信任的局域网里使用；需要外网访问时用 Tailscale、ZeroTier 等组网工具，不要把端口直接暴露到公网。
- **诊断模式**下临时文件不会自动删除，用完记得关闭。
- 反复启用、关闭 JRP 或切换捕获方式后，仍可能偶发单键雨条缺失，重启游戏可以恢复（1.1.1 起的已知问题）。

## 给 Mod 作者

公共 API 只新增、不修改：

- 新增 `ChartRenderQualityTier` 枚举（`Custom`、`Small`、`Standard`、`High`、`NearLossless`）和 `ChartRenderRequest.QualityTier`。默认值为 `Custom`，原有调用方的行为完全不变。
- 用 `ChartRenderApi.CreateRequestFromCurrentSettings()` 创建请求的调用方（例如 Creplay）会自动使用玩家在设置页选的档位。
- 恒定码率仍然优先于档位；ProRes 忽略档位。

API 文档位于仓库中的 `Doc/Api/ChartRendering.md`。
