# ADOFAI Editor Tweaks - Chart Rendering 1.1.0

这是 Chart Rendering 作为独立 Mod 发布后的首个大版本，也是离殇i 接手维护后的第一个版本。

本次更新从 v1.0.3 跨越至 v1.1.0，带来了多项重要改进：新增多种视频编码格式和硬件编码支持，重构画质与编码速度设置，改善高分辨率渲染体验，并对渲染流程、稳定性和性能进行了大量优化。

部分渲染改进移植自 sui 的 CheryTools AET Recorder，已获得作者同意。感谢 lizi 协助审核代码，也感谢参与内测并提供反馈的朋友们。

## 下载与安装

1. 下载下方附件 `ADOFAI.EditorTweaks.ChartRendering-1.1.0.zip`（约 85 MB，已内置 FFmpeg）。
2. 将压缩包解压到游戏目录的 `Mods\` 文件夹中。已安装旧版本的用户可以直接覆盖，建议提前备份原来的 `Mods\ADOFAI.EditorTweaks.ChartRendering\` 文件夹。
3. 启动游戏，在编辑器中按 **Ctrl + Shift + E** 打开设置页面。

**运行要求：** Unity Mod Manager 0.27.0 或更高版本。

Creplay 等调用 Chart Rendering API 的 Mod 无需更新，可以继续使用原有版本（音频缓冲大于 256 时的音效问题见「已知问题」）。

## 升级前请注意

本次更新调整了部分编码行为，升级后可能与旧版本产生以下差异：

- **默认编码方式发生变化：** 当视频码率设置为 0（默认值）时，现在会使用 CRF（恒定质量）模式编码，而 v1.0.3 使用的是带上限的可变码率。因此，同一张谱面导出的视频体积可能与旧版本不同。如果需要固定码率，可以填写视频码率，或开启新增的「恒定比特率」选项。
- **安装包体积增加：** 安装包增大至约 85 MB，因为本次更换为完整版 FFmpeg，以支持更快的 AV1 编码以及 H.266/VVC 编码。

## 新增功能

### 更多视频编码格式

在原有 H.264 的基础上，新增以下编码格式：

- **HEVC / H.265：** 在画质相近的情况下，可以获得更小的视频体积。
- **AV1：** 新一代视频编码格式，兼顾压缩效率与画质。
- **ProRes 422 HQ：** 面向高质量视频制作的编码格式，适合后期编辑与二次处理。
- **H.266 / VVC（实验性）：** 新一代高压缩率编码格式，目前仅支持 CPU 编码，速度非常慢，且大多数播放器和视频网站尚不支持，仅供尝鲜，不建议日常使用。

### AMD / Intel 硬件编码支持

此前硬件编码主要依赖 NVIDIA 显卡，本次新增 AMD 和 Intel 显卡的硬件编码支持，包括独立显卡与核芯显卡。

- 默认自动选择可用的硬件编码器，优先级为 NVIDIA → AMD → Intel。
- 也可以在「详细编码设置」中手动指定编码设备。
- 如果指定的显卡不可用，会自动回退到 CPU 编码。
- AV1 硬件编码需要 NVIDIA RTX 40 系、AMD RDNA 3、Intel Arc 或更新的显卡。较老的显卡会自动使用 CPU 的 SVT-AV1 编码，相比此前也有明显的速度提升。

### 编码器检测

新增编码器检测功能，让用户能够更直观地了解当前设备的编码能力。

- 总览页面会显示当前电脑支持的编码器。
- 渲染设置页面会显示本次渲染实际使用的编码器。
- 不可用的编码选项会自动置灰。
- 更换显卡或 FFmpeg 后会自动重新检测；更新显卡驱动后，请手动点击「重新检测」。

### 更灵活的画质与速度控制

新增多项高级编码设置，允许用户根据实际需求调整输出效果。

- **恒定比特率（CBR）：** 开启后按照指定码率输出视频；码率设置为 0 时使用推荐码率。
- **编码器选择：** 可以在「详细编码设置」中指定使用显卡、CPU 或自定义编码器。
- **编码预设：** 根据所选编码器提供不同的速度预设。显卡编码支持 p1～p7，CPU 编码支持 ultrafast～veryslow。

### 游戏画面模式支持高分辨率

游戏画面模式现在支持输出高于当前显示器分辨率的视频。

例如，即使使用 1080p 显示器，也可以渲染 4K 视频。高分辨率画面仅用于最终输出，屏幕上仍然只显示预览。

### 稳定性与诊断功能

- **关闭保护：** 渲染期间第一次尝试关闭游戏时会被拦截并提示，10 秒内再次尝试关闭才会真正退出，降低误操作导致渲染中断的风险。
- **断线提示：** 如果游戏意外关闭或崩溃，设置页面会显示提示，说明当前渲染可能已经中断。
- **独立渲染日志：** 每次渲染都会单独保存日志至 `Workspace\Logs\render_*.log`，自动保留最近 10 份，反馈问题时可以直接附上。
- **自定义 FFmpeg 路径：** 支持指定自己的 `ffmpeg.exe`。如果路径无效，会自动回退到软件内置的 FFmpeg。

## 渲染流程与性能改进

除了新增功能，本次还对原有渲染流程进行了多项优化：

### 更清晰的渲染进度

进度条现在分为三个阶段：

- 画面捕获：0%～90%
- 完成编码：90%～92%
- 合成音频：92%～100%

进入音频合成阶段后，会明确提示「请勿关闭游戏」，避免用户误以为渲染已经完成。

### 提高导出文件的可靠性

视频现在会先输出到 `.part` 临时文件，只有在渲染全部完成后才会重命名为正式文件。

因此，导出目录中使用正式文件名的视频一定是完整的，不会再因为渲染中断而留下看似正常、实际无法播放的文件。

### ProRes 编码优化

- ProRes 编码速度提升约 3 倍。
- 优化输出文件体积，使其更加合理。
- 选择 ProRes 时自动切换至 MOV 容器。
- MOV 容器下的 FLAC 音频会自动切换为同样无损的 ALAC。

### 渲染结束与取消操作优化

- 渲染完成后自动返回编辑器，不再需要手动按 Esc。
- 改进取消渲染的处理机制，减少取消操作无响应的情况。
- 取消渲染后自动删除尚未完成的视频文件。

### 减少画面复制

减少了不必要的整帧画面复制，高分辨率（尤其是 4K）渲染时速度更快。

### 临时文件管理优化

- 每次渲染都会创建独立的临时文件夹。
- 取消渲染后可以立即开始下一次渲染，不再受上一次残留临时文件的影响。
- 开始新的渲染时，会清理残留超过 1 小时的旧临时文件夹。

### Apple 设备兼容性改进

HEVC 视频现在使用 `hvc1` 标签，改善在 Apple 设备上的直接播放兼容性。

## 问题修复

本次修复了多个影响渲染结果、操作体验及兼容性的问题：

- 修复同一张谱面第二次开始渲染时，导出视频没有音乐的问题。
- 修复星球自转、彩虹星球、Miss 闪光、打击停顿、镜头后坐及文字装饰抖动等效果，在渲染视频中的播放速度快于游戏内实际表现的问题。
- 修复渲染过程中点击「取消」无响应的问题，CPU 使用慢速预设时尤为明显。
- 修复音频合成阶段进度条停留在 100% 不动的问题，并避免此时关闭游戏留下损坏的视频。
- 修复选择 HEVC、AV1 或 ProRes 编码时，实际输出仍然使用 H.264 的问题。
- 修复 ProRes 编码失败的问题。
- 修复 MOV 容器搭配 FLAC 音频时合成失败的问题。
- 修复音频缓冲设置大于 256 时，官方谱面或 Bundle 谱面渲染失败的问题。
- 修复音频缓冲切换失败后，原有音频设置未能恢复的问题。
- 修复自定义 FFmpeg 路径包含非法字符时，渲染直接报错的问题。
- 修复「Finalizing video」阶段的文字未正确翻译的问题。

## 已知问题与注意事项

- **AMD / Intel 硬件编码：** 尚未在所有显卡型号上完成验证。如果遇到编码问题，可以在「详细编码设置」中切换至 CPU 编码，并反馈显卡型号和驱动版本。
- **CBR 支持范围：** 目前只有 NVIDIA 和 AMD 显卡编码能够实现真正的恒定码率；CPU 编码只能做到近似恒定码率。H.266 不支持 CBR，会自动使用可变码率；ProRes 的码率由编码格式本身决定，CBR 设置对其无效。
- **H.266 编码速度：** 目前仍然非常慢，1080p60 大约每秒只能处理几帧，仅建议使用短片段进行体验。
- **音频缓冲大于 256：** 渲染期间会临时切换音频设置。渲染完成后，其他 Mod 自行加载的音效（例如 Creplay 的按键音）可能需要重新进入谱面才能恢复。
- **多显卡设备：** 自动选择编码器时按照 NVIDIA → AMD → Intel 的优先级执行，不会根据游戏实际使用的显卡进行选择。如果需要使用特定显卡，请手动指定。

## 给 Mod 作者

本次更新对公共 API `ADOFAI.EditorTweaks.Api.Rendering` 进行了扩展，新增内容均保持向后兼容，原有调用方无需修改代码。

新增 API 包括：

- `ChartRenderRequest.VideoCodec` 和 `ChartRenderVideoCodec`：支持 `H264`、`Hevc`、`Av1`、`ProRes`、`Vvc`。
- `ChartRenderRequest.HardwareEncoder` 和 `ChartRenderHardwareEncoder`：支持 `Auto`、`Nvidia`、`Intel`、`Amd`。
- `ChartRenderRequest.HardwarePreset` / `CpuPreset` 及对应枚举。
- `ChartRenderRequest.ConstantBitrate`。
- 游戏画面模式现在会使用请求中的 `Width` / `Height` 参数；当宽高为 0 时，仍然按照游戏窗口尺寸截取画面。

请注意，**码率为 0 时默认改用 CRF 编码**，可能导致升级后输出视频的文件体积发生变化。

更多 API 说明请参考仓库中的 `Doc/Api/ChartRendering.md`。

## 问题反馈

如果遇到渲染异常或其他问题，请在 Issues 中提交反馈，并尽可能附上以下信息：

- 显卡型号及驱动版本。
- 游戏版本。
- 使用的编码格式和容器。
- 对应的 `render_*.log` 渲染日志。
- `Player.log` 游戏日志，路径如下：

  `%USERPROFILE%\AppData\LocalLow\7th Beat Games\A Dance of Fire and Ice\Player.log`

- 问题的具体复现步骤。

提供的信息越完整，越有助于定位和解决问题。
